━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PHASE 1 — AMAZON S3 BUCKET
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Login to AWS Console → Search "S3" → Click S3

2. Click "Create bucket"

3. Fill in:
   Bucket name    : aws-batch-uploads-2024
   AWS Region     : ap-south-1 (Asia Pacific — Mumbai)

4. "Object Ownership" → Keep default (ACLs disabled)

5. "Block Public Access settings for this bucket"
   → KEEP ALL 4 CHECKBOXES TICKED (private bucket)

6. "Bucket Versioning" → Click "Enable"

7. "Default encryption"
   Encryption type     : Server-side encryption with Amazon S3 managed keys (SSE-S3)
   Bucket Key          : Enable

8. Click "Create bucket" ✅

9. Click on the bucket → "Properties" tab
   → Note the Bucket ARN: arn:aws:s3:::aws-batch-uploads-2024
   (you will need this for IAM policy)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PHASE 2 — DYNAMODB TABLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. AWS Console → Search "DynamoDB" → Click DynamoDB

2. Click "Create table"

3. Fill in:
   Table name          : FileUploads
   Partition key       : RecordId    (type: String)
   Sort key            : Leave EMPTY

4. "Table settings" → Select "Customize settings"

5. "Table class" → DynamoDB Standard

6. "Read/write capacity settings" → On-demand (Free tier friendly)

7. "Encryption at rest" → Owned by Amazon DynamoDB (default)

8. Click "Create table" ✅

   → Your table will be in "Active" state in ~30 seconds

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PHASE 3 — AMAZON SES (EMAIL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

NOTE: By default SES is in "Sandbox" mode.
      In Sandbox, BOTH sender AND recipient emails must be verified.
      For a student project, this is fine.

STEP 3A — Verify your SENDER email:

1. AWS Console → Search "SES" → Click "Amazon Simple Email Service"

2. Left sidebar → "Verified identities" → Click "Create identity"

3. Identity type → Email address

4. Email address → Type YOUR email (e.g. youremail@gmail.com)
   This will be the FROM address.

5. Click "Create identity"

6. AWS will send a verification email → Open your email → Click the link ✅

STEP 3B — Verify a RECIPIENT test email (for Sandbox):

1. Repeat steps 2-6 above with the email you want to test receiving on.
   (Can be the same email or a second one)

STEP 3C — Note: In Production
   → Request SES Production Access (takes ~24 hours for AWS approval)
   → Once approved, you can send to ANY email without pre-verifying
   → For this student project, sandbox mode is perfectly fine

PHASE 4 — IAM ROLE (Most Important Step!)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHY? Instead of putting AWS Access Keys in the code (dangerous!),
     we give the EC2 instance a "Role" — it automatically gets
     permission to talk to S3, DynamoDB, and SES.

STEP 4A — Create a custom Policy:

1. AWS Console → Search "IAM" → Click IAM

2. Left sidebar → "Policies" → Click "Create policy"

3. Click "JSON" tab → Paste this policy:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "S3Access",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::aws-batch-uploads-2024",
        "arn:aws:s3:::aws-batch-uploads-2024/*"
      ]
    },
    {
      "Sid": "DynamoDBAccess",
      "Effect": "Allow",
      "Action": [
        "dynamodb:PutItem",
        "dynamodb:GetItem",
        "dynamodb:UpdateItem",
        "dynamodb:DeleteItem",
        "dynamodb:Scan",
        "dynamodb:Query"
      ],
      "Resource": "arn:aws:dynamodb:ap-south-1:*:table/FileUploads"
    },
    {
      "Sid": "SESAccess",
      "Effect": "Allow",
      "Action": [
        "ses:SendEmail",
        "ses:SendRawEmail"
      ],
      "Resource": "*"
    }
  ]
}

4. Click "Next"

5. Policy name  : EC2-FileUpload-Policy
   Description  : Allows EC2 to access S3, DynamoDB, and SES for file upload app

6. Click "Create policy" ✅

STEP 4B — Create the IAM Role:

1. Left sidebar → "Roles" → Click "Create role"

2. Trusted entity type → AWS service
   Use case → EC2
   → Click "Next"

3. Search for "EC2-FileUpload-Policy" → Tick the checkbox
   → Click "Next"

4. Role name  : EC2-FileUpload-Role
   Description: IAM role for AWS batch student file upload EC2 instance

5. Click "Create role" ✅

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PHASE 5 — EC2 INSTANCE LAUNCH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. AWS Console → Search "EC2" → Click EC2

2. Click "Launch instance"

3. Name: aws-batch-upload-server

4. Application and OS Images:
   → Click "Browse more AMIs"
   → Search: "Amazon Linux 2023"
   → Select: Amazon Linux 2023 AMI (64-bit x86)
   → Click "Select"

5. Instance type:
   → Search and select: t2.medium

6. Key pair (login):
   → Click "Create new key pair"
   Key pair name : aws-batch-keypair
   Key pair type : RSA
   Private key format : .pem (for Mac/Linux) or .ppk (for Windows PuTTY)
   → Click "Create key pair"
   → SAVE the downloaded .pem file safely! You cannot download it again.

7. Network settings → Click "Edit":
   VPC             : Default VPC
   Subnet          : No preference (any AZ)
   Auto-assign IP  : Enable
   
   Firewall (Security Group):
   → Click "Create security group"
   Security group name : aws-batch-upload-sg
   Description         : Security group for file upload app
   
   Inbound rules:
   Rule 1: SSH
     Type: SSH  | Port: 22  | Source: My IP (or 0.0.0.0/0 for students)
   
   Rule 2: HTTP
     Type: HTTP | Port: 80  | Source: 0.0.0.0/0
   
   (Click "Add security group rule" to add Rule 2)

8. Configure storage:
   → Change from 8 GB to 20 GB (gp3)

9. Advanced details → IAM instance profile:
   → Click dropdown → Select "EC2-FileUpload-Role"

10. Review → Click "Launch instance" ✅

11. Wait 2-3 minutes → Click your instance → Copy "Public IPv4 address"
    Example: 13.232.45.67

PHASE 6 — UPLOAD CODE TO EC2
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OPTION A — Using SCP (Mac/Linux terminal):

  scp -i /path/to/aws-batch-keypair.pem \
      /path/to/aws-upload-app.zip \
      ec2-user@<YOUR-EC2-IP>:/home/ec2-user/

OPTION B — Using WinSCP (Windows):
  1. Download WinSCP (free)
  2. File protocol: SCP
  3. Host: <YOUR-EC2-IP>
  4. Username: ec2-user
  5. Click "Advanced" → SSH → Authentication → Browse for .pem file
  6. Connect → Drag and drop the zip file

OPTION C — Using EC2 Instance Connect (Browser, easiest):
  1. In EC2 Console → Select your instance
  2. Click "Connect" → "EC2 Instance Connect" → Click "Connect"
  3. In the browser terminal, upload via:
     curl -o aws-upload-app.zip "YOUR_GITHUB_RAW_URL"
  (Or push the code to GitHub and clone it — see Phase 7)

PHASE 8 — RUN THESE COMMANDS ON EC2 (copy-paste each block)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# --- STEP 1: Update system and install dependencies ---
sudo dnf update -y
sudo dnf install -y python3 python3-pip nginx unzip git

# --- STEP 2: Extract the uploaded zip ---
cd /home/ec2-user
unzip aws-upload-app.zip
ls -la aws-upload-app/

# (OR if using GitHub)
# git clone https://github.com/YOUR_USERNAME/aws-upload-app.git

# --- STEP 3: Go into the app folder ---
cd aws-upload-app

# --- STEP 4: Create a Python virtual environment ---
python3 -m venv venv
source venv/bin/activate

# --- STEP 5: Install Python packages ---
pip install --upgrade pip
pip install -r requirements.txt

# --- STEP 6: Edit the .env file with your values ---
nano .env

  # Change these lines:
  AWS_REGION=ap-south-1
  S3_BUCKET_NAME=aws-batch-uploads-2024
  DYNAMODB_TABLE=FileUploads
  SES_SENDER_EMAIL=your-verified-email@gmail.com   ← Change this!

  # Save: Ctrl+O → Enter → Ctrl+X

# --- STEP 7: Test the app is working (quick test) ---
python app.py
  # You should see: Running on http://0.0.0.0:5000
  # Press Ctrl+C to stop

# --- STEP 8: Set up Nginx ---
sudo cp nginx.conf /etc/nginx/conf.d/flask-app.conf
sudo nginx -t        # Should say: syntax is ok / test is successful
sudo systemctl start nginx
sudo systemctl enable nginx

# --- STEP 9: Create log directory ---
sudo mkdir -p /var/log/flask-app
sudo chown ec2-user:ec2-user /var/log/flask-app

# --- STEP 10: Set up systemd service (auto-start on reboot) ---
sudo cp flask-app.service /etc/systemd/system/flask-app.service
sudo systemctl daemon-reload
sudo systemctl start flask-app
sudo systemctl enable flask-app

# --- STEP 11: Check if everything is running ---
sudo systemctl status flask-app
sudo systemctl status nginx

# Both should show: Active: active (running)

# --- STEP 12: Check logs if something fails ---
sudo journalctl -u flask-app -f         # Flask app logs
sudo tail -f /var/log/flask-app/error.log   # Gunicorn error log
sudo tail -f /var/log/nginx/error.log       # Nginx error log

TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem: Can't access http://<IP> in browser
Fix:     Check Security Group → Port 80 is open to 0.0.0.0/0
         sudo systemctl status nginx   → must be running
         sudo systemctl status flask-app → must be running

Problem: "403 Forbidden" on S3 upload
Fix:     Verify IAM Role is attached to EC2 instance
         EC2 Console → Instance → Security tab → IAM Role

Problem: Email not received
Fix:     Verify SES_SENDER_EMAIL in .env is the verified email
         Check SES Console → Verified Identities
         Both sender AND recipient must be verified (Sandbox mode)

Problem: DynamoDB error
Fix:     Check IAM Policy allows DynamoDB access to table "FileUploads"
         Verify region in .env matches where you created the table

Problem: Flask app won't start
Fix:     source venv/bin/activate && python app.py
         Check for import errors or missing packages
         pip install -r requirements.txt
